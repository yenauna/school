# 현장 사용 시뮬레이션 결과

검증일: 2026-11-17 (한국 시간). Chromium PC 1600×1000, 모바일 412×900 및 740×360 가로 모드.

실제 Supabase `grade6-2026`은 읽거나 수정하지 않았습니다. 브라우저별 Supabase 요청을 전부 가로채는 revision 검사 모의 RPC와 독립적인 브라우저 세션 6개를 사용했습니다. 실제 학생 자료는 사용하지 않았습니다.

## 추가 기능

- 원격 main의 포인터 드래그를 통합했습니다. 모바일은 학생을 200ms 길게 누르거나 가로로 끈 뒤 이동합니다. 70px 가장자리 스크롤과 PC의 이름 위 드래그, 수정 창의 빠른 반 이동도 유지합니다. 위·아래 가장자리에서 프레임 단위로 스크롤하며, 화면 밖 반으로 놓을 수 있습니다. 일반 손가락 스크롤과 구분하고 고정 학생은 잠급니다. 터치 취소·다중 터치·탭 전환·화면 숨김 때 이동을 취소하고 드래그 표시를 정리합니다. 드래그 중 서버 갱신으로 카드가 교체되지 않습니다.
- `경고만 최소 조정`은 현재 배정을 출발점으로 경고 학생과 필요한 교환 상대만 탐색합니다. 올바른 고정 반과 충족된 필수 조합을 보존하고 총원 오차를 늘리지 않습니다. 제약 경고 감소를 우선하며, 제약 경고가 없을 때는 설정된 별점 차이도 줄입니다. 한 번의 실행 취소로 복원합니다. 탐색은 3,000개 후보·16단계 이내이므로 전역 최소 이동을 보장하지 않으며, 모순된 제약 등 해결하지 못한 경고는 그대로 표시합니다.
- 이전 요청의 고정 반 자동 이동·필수 조합 동반 이동 확인, 별점 기준 저장/빨간불, 기본 남녀 좌우 배치, 슬림 하단 바, 인원 알약 통합도 함께 검증했습니다.

## 발견 및 수정

| 등급 | 문제 | 수정 및 검증 |
| --- | --- | --- |
| P1 | 여섯 명이 같은 revision에서 저장하면 기존 재시도 3회로는 마지막 저장자가 완료하지 못함 | 재병합 재시도 한도 12회. 동시 저장 충돌 15회를 처리하고 명단 108명·조건 18개 보존 |
| P1 | 학생 숫자 ID 동시 사용 및 저장 도중 추가 편집 시, 재번호 부여 후 다른 학생과 섞일 수 있음 | 신규 학생의 안정적인 `clientId`, 기준/현재 자료의 참조 ID 동시 정렬, 단조 증가 `nextId`. 원격 추가·저장 중 이름 변경·두 번째 학생 추가를 모두 보존 |
| P1 | 파일 이어 올리기가 이름만 비교해 다른 반 동명이인을 누락 | 반·번호·이름으로 중복 판정. 다른 반 동명이인은 추가하고 같은 파일 재입력은 중복 추가하지 않음 |
| P1 | 첫 배정·다시 배정 후 탭 전환이 저장 타이머를 취소해 결과가 공유되지 않음 | 결과 탭 전환 후 저장 예약. 6인 병합 자료로 실제 배정하고 서버 저장·다른 화면 반영까지 검증 |
| P1 | 명단 메타데이터 병합이 공유 배정 결과까지 초기화할 수 있음 | 학생 ID로 배정 배열을 정렬·보존. 신규 미배정 학생이 생긴 경우에만 재배정 필요 처리 |
| P2 | 결과 갱신 시 모바일에서 보던 행이 약 80px 움직임 | 현재 보이는 학생 행을 기준으로 상대 스크롤 복원. 통합본 실행 위치 변화 0.453px |
| P2 | 갱신 스크롤·자동 안내 배너 정리 등 레이아웃 변경이 사용자 스크롤로 기록되어 유휴 정지를 방해 | 서버 스크롤 보정·배너 자동 정리는 활동 기록에서 제외하고 상태 표시줄 폭·높이를 안정화. 무조작 정지·클릭 재개 확인 |
| P2 | 좁은 남녀 좌우 배치에서 고정 표시가 포함된 행이 두 줄이 됨 | 레이아웃 선택자의 우선순위 수정, 이름 말줄임과 전체 이름 툴팁. 고정 행 높이 31px 이하 확인 |

점검 범위에서 P0는 발견되지 않았으며, 수정 후 재현되는 P1은 없었습니다.

| 그룹 참조 및 전출예정·사용자 태그 | 모든 그룹 구성원이 원래 입력 반에 속함. 전출예정 6명 및 태그 보존 |
| 명단·조건 대기 및 다른 반 업데이트 | 자동 서버 읽기/저장 없음. 6개 화면 수동 업데이트 후 모두 108명 |

| 그 밖의 경고 조정 | 고정 반 불일치·통합학급 미지정·특수 중복·3년 같은 반·필수 조합 분리 회복 및 불가능 제약 유지 테스트 통과 |
| 이전 결과 기능·PC/모바일 화면 | Chromium 회귀, 동반 이동 확인/취소, 별점 기준 저장, 인원 문구, 40px 이하 하단 바 검증 통과 |

단위 테스트 33개와 브라우저 스크립트 5개를 통과했습니다. 각 스크립트가 출력하는 `/tmp/bbj-*` 경로에 화면 캡처를 생성합니다.

## 재현 명령

저장소 루트에서 `python -m http.server 4190` 실행 후:

```sh
node --test banbaejeong/tests/core.test.cjs
BBJ_URL=http://127.0.0.1:4190/banbaejeong/ node banbaejeong/tests/browser.cjs
BBJ_URL=http://127.0.0.1:4190/banbaejeong/ node banbaejeong/tests/drag.cjs
BBJ_URL=http://127.0.0.1:4190/banbaejeong/ node banbaejeong/tests/collaboration.cjs
BBJ_URL=http://127.0.0.1:4190/banbaejeong/ node banbaejeong/tests/result-controls.cjs
BBJ_URL=http://127.0.0.1:4190/banbaejeong/ node banbaejeong/tests/field-simulation.cjs
```

Playwright와 `/usr/bin/chromium`이 필요합니다. 위 스크립트는 실제 서버 저장을 사용하지 않습니다. 모의 RPC의 충돌 횟수와 반영 시간은 실행 시점에 따라 달라질 수 있습니다. 실기기 Safari/Chrome 및 실제 네트워크 지연은 이번 검증에 포함하지 않았습니다.
